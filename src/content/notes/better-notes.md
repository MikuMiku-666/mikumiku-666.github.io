一篇笔记有没有用，不在于它有多长，而在于过一段时间再打开时，我们能否快速回到当时的思路。

## 从一个具体问题开始

与其写「今天学习了 JavaScript」，不如写「为什么循环中的异步任务没有按顺序执行」。一个具体问题，能给笔记一个清晰的入口。

记录问题出现的场景，保留最小可复现的例子。几行能运行的代码，往往比大段截图更容易理解。

## 用自己的话解释

先试着离开原文，用自己的语言说一遍。如果解释不清楚，那个地方可能正好值得继续研究。

可以用这样的结构：

```text
问题：我想完成什么？实际发生了什么？
原因：哪些条件导致了这个结果？
方案：我选择了什么？为什么？
验证：我如何确认问题已经解决？
```

## 留下一个可以验证的例子

下面这个简单函数，把预期写进了代码：

```javascript
function average(numbers) {
  if (numbers.length === 0) return 0;
  return numbers.reduce((sum, value) => sum + value, 0) / numbers.length;
}

console.assert(average([2, 4, 6]) === 4);
console.assert(average([]) === 0);
```

记录正常情况，也记录边界情况。未来回来看，就知道这个结论是在什么范围内成立的。

## 让更新比重写更容易

给笔记起一个稳定的文件名，之后继续补充，而不是每次都新开一篇。

在文章顶部增加 `updated` 日期，就能让读者知道这篇文章最近修订过。旧结论被修正也是记录的一部分。

> 这些是示例写作建议。找到适合自己的节奏，比坚持一种固定格式更重要。
