文字适合讲清思路，图片适合展示细节，视频适合演示过程，PDF 适合附上完整资料。这篇示例把它们放在一起，作为以后写作时的参考。

## 写好 Markdown 的基本结构

用标题分段，用列表整理步骤，用引用强调一小段话。不要为了样式给每句话加粗，让重点自然出现。

```markdown
## 这次学到了什么

这是一段普通文字，其中有一个 **关键结论**。

- 写下问题
- 解释解决过程
- 附上验证结果

> 给未来的自己，留一句提醒。
```

表格适合比较少量信息：

| 内容       | 推荐格式        | 使用场景       |
| ---------- | --------------- | -------------- |
| 思路与过程 | Markdown        | 日常学习笔记   |
| 截图与图解 | PNG / JPG / SVG | 展示细节       |
| 项目演示   | MP4             | 操作与动画     |
| 完整资料   | PDF             | 报告与阅读材料 |

## 插入一张图片

把图片放入 `public/images/`，写作时从 `/images/` 开始引用。部署到 GitHub Pages 的仓库路径会自动补齐。

![保持好奇、写下思考、动手分享](/images/learning-map.svg)

```markdown
![图片说明](/images/learning-map.svg)
```

也支持文章旁的相对路径图片。图片较多时，建议按文章分文件夹，文件名尽量有含义。

## 纯 Markdown 也可以

如果不需要组件，普通 `.md` 文件也可以直接使用 HTML：

```html
<video controls playsinline preload="metadata" src="/media/demo.mp4"></video>

<iframe src="/media/example.pdf" title="项目报告" width="100%" height="500"></iframe>

<a href="/media/example.pdf">下载 PDF</a>
```

同站的链接、图片，以及这些带引号的 HTML 地址，都会适配 GitHub Pages 的仓库路径。代码块中的示例保持原样。
