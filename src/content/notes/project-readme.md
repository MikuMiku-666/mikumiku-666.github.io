当一个新想法出现时，先给它写一份很短的 README。这个动作能帮助我们把「好像很有趣」变成「知道从哪里开始」。

## 一句话，说清楚要解决什么

比如：一个只记录「想读、在读、读完」的阅读清单。范围清楚，第一版就容易完成。

先写使用场景，再决定需要什么功能。新冒出来的好点子，可以放进「以后再做」里。

## 给第一版画一条边界

| 第一版要做       | 以后再考虑     |
| ---------------- | -------------- |
| 添加一本书       | 多人共享       |
| 修改阅读状态     | 自动推荐       |
| 保留一段简短感想 | 复杂的评分体系 |

这不是永久的限制，只是为了能走完从开始到完成的过程。

## 记录过程里的选择

为什么选这个技术？哪些部分没有按计划进行？如果重做一次，会换一种方式吗？

这些过程往往比功能截图更能体现一个项目的价值。把它们放进项目详情页，也能成为下一次实践的参考。

## 留下一个可以继续的下一步

与其只写「待完善」，不如写「下一步：让筛选条件保留在页面地址里」。具体的下一步，可以让中断后的重新开始轻松一点。
